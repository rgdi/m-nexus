## 2. PWA — cómo funciona

### 2.1 El service worker anterior estaba roto

```js
// sw.js v2.0.0 — NUNCA FUNCIONÓ
const ASSETS = [
  './src/services/*.js',   // ← caches.addAll NO expande globs
  './src/widgets/*.js',    // ← la instalación fallaba en silencio
];
```

Dos fallos:
1. `caches.addAll()` no expande patrones glob. Un solo 404 rechaza todo el lote.
2. **Nunca se registró** desde la app, así que el worker no se ejecutaba.

### 2.2 El service worker actual

```
sw.js  (VERSION = v2.36.2)
  ├─ importScripts("/sw-precache.js")   ← 114 módulos generados
  ├─ install   → precachea SHELL (16) + MODULES (114) en lotes de 12
  ├─ activate  → borra cachés old, clients.claim()
  ├─ fetch
  │    ├─ /api/*          → NUNCA cachea (van al outbox)
  │    ├─ upgrade:websocket → no intercepta
  │    ├─ navigate       → network-first, fallback a index.html cacheado
  │    └─ estáticos      → stale-while-revalidate (RUNTIME_CACHE)
  ├─ sync     → Background Sync, tag "mnexus-outbox-sync"
  └─ message  → skip-waiting, register-sync, get-version
```

### 2.3 Precache manifest

`sw-precache.js` se genera con:

```bash
python3 scripts/gen-sw-precache.py
```

Un test (`frontend/tests/v236.test.js`) **falla si el manifest está desactualizado**, así que no se puede olvidar regenerarlo.

> ⚠️ `const MODULES` en el scope del worker **no** es `self.MODULES`. Por eso el
> generador emite `self.MODULES = MODULES;` explícitamente. Ese detalle costó
> una iteración de debug (el precache se quedaba en 16 archivos).

### 2.4 Offline verificado

```
First load  → SW installa → 118 archivos en mnexus-shell-v2.36.2
setOffline(true) → reload
  route: "study"
  display: "TARJETAS DE ESTUDIO"
  statTiles: 3, startBtn: true, tabbar: true
```

Los fetches al backend fallan con `ERR_INTERNET_DISCONNECTED` (esperado) y las
mutaciones se encolan en el outbox de IndexedDB.

### 2.5 Autosync

- `offline_queue.js` → `drainNow()` nuevo en v2.36.0
- El SW pide el sync vía `postMessage({type:"mnexus-sync-request"})`
- La página responde con `drainNow()`
- Además: listener `online` + poll de 30s como red de seguridad
- `mnexus-outbox-changed` → re-registra el sync tag

## 3. Flashcards — tipos y grading

### 3.1 Tipos soportados

```ts
type CardType =
  | "basic" | "cloze" | "enumerate"
  | "image_occlusion"
  | "multiple_choice"   // opción múltiple
  | "typed_answer"       // respuesta escrita cerrada  ← NUEVO
  | "drag_gap";          // arrastrar a la casilla     ← NUEVO
```

### 3.2 Respuesta escrita cerrada (typed_answer)

`POST /api/v1/grade/typed`

```json
{ "userAnswer": "la presion aortica es 120 mmHg",
  "expected": "120 mmHg",
  "context": "...", "useLlm": true }
```

Cadena de evaluación (5 niveles, se detiene en el primero que aplica):

| Nivel | Cuándo | `gradedBy` | Score |
|-------|--------|-----------|-------|
| 1. Exacto | `userAnswer === expected` | `exact` | 100 |
| 2. Normalizado | sin tildes/puntuación/case | `normalized` | 100 |
| 3. F1 de tokens | F1 ≥ 0.85 | `tokens` | F1×100 |
| 4. **LLM** | 0.2 < F1 < 0.85 y hay proveedor | `llm` | judge's score |
| 5. Determinista | resto | `tokens` | F1×100 |

Si no hay LLM disponible, **degrada al nivel 5 y lo dice** en `gradedBy`, para
que la UI solo muestre "revisado por IA" cuando de verdad lo fue.

Respuesta real:
```json
{
  "score": 57, "verdict": "partial", "gradedBy": "tokens",
  "feedback": "Correcto, pero con palabras de más: presion, aortica, es.",
  "matched": ["120", "mmhg"], "missed": [], "extra": ["presion","aortica","es"],
  "correctAnswer": "120 mmHg"
}
```

Stopwords ES+EN filtrados antes del F1, para que "la" o "the" no cuenten.

### 3.3 Opción múltiple (multiple_choice)

`POST /api/v1/grade/mcq`

**Re-chequea en servidor.** Si mandas `cardId`, lee la card de
`flashcards.json` y decide ahí. Un cliente modificado no puede autoaprobarse.
Si no mandas `cardId`, acepta `options` + `correctIndex` (para el preview
antes de persistir).

Devuelve `perChoice[]` con `correct` y `chosen` por opción, para pintar la
UI sin lógica duplicada.

### 3.4 Drag-gap

`widgets/drag_gap.js` — huecos `___` + fichas arrastrables.

- **Pointer Events**: ratón, dedo y lápiz con el mismo código
- **Ruta accesible**: tap ficha → tap hueco (sin drag)
- Colocación incorrecta: rebota + `@keyframes m-slot-shake`
- Colocación correcta: se fija en verde + `@keyframes m-slot-pop`
- Devuelve `perGap[]` + `durationMs` a `onComplete` para el log FSRS

## 4. Logging

```js
import { createLogger } from "./services/pwa.js";
const log = createLogger("mi-modulo");

log.debug(...)   // solo si localStorage.mnexus.debug === "1" o localhost
log.info(...)
log.warn(...)    // siempre
log.error(...)   // siempre
```

Activar debug:
```js
localStorage.setItem("mnexus.debug", "1");
```

Backend usa el logger estructurado existente (`logOp`, `logError`,
`logNetwork`). El grader añade:
```ts
logOp("grading", "typed", true, { gradedBy, score, durationMs });
```
