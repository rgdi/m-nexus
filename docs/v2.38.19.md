## 1. El canal: lo perdido, entregado o dicho

Quedaba un agujero y era el peor de todos, porque no se manifestaba
como un fallo sino como unapantalla que parecía correcta.

### Reconectar era garantizar perder lo perdido

El servidor, al abrir el canal, mandaba:

```
hello  { revision: <la revisión actual del servidor> }
...    change { revision: 2 }
...    change { revision: 3 }
```

El cliente, al recibir `hello`, **adoptaba esa revisión**. Los `change`
que venían después eran "viejos" (`revision <= la que ya tengo`) y se
descartaban. Los descartaba **justo en el caso para el que existen**:
el de recuperar lo que se te pasó mientras no estabas.

Consecuencia: el servidor sí guardaba el backlog, sí lo reenviaba, y el
cliente lo tiraba a la basura sin decir nada. El `since` estaba en la
URL, el historial estaba en memoria, y aun así te quedabas sin los
cambios.

Ahora el protocolo es:

```
hello  { revision: <la que el cliente DICE tener>, current, since, truncated }
...    change { revision: 2 }      ← el backlog, que ahora sí se aplica
...    change { revision: 3 }
synced { revision: 3, truncated }  ← cierre: a partir de aquí va bien
```

### El hueco que no se puede cubrir, dicho

El historial son 200 eventos y 10 minutos. Si vuelves después de eso, lo
que se perdió ya no está — y antes no se decía nada: `hello` traía la
revisión actual, el cliente la aceptaba, y se quedaba **creyendo que
estaba al día con datos viejos para siempre**.

Ahora el servidor manda `truncated` cuando `since` es anterior a lo más
antiguo que queda guardado, y el cliente lo marca (`liveState().gap`) y
lo **avisa a quien esté escuchando** con `{ gap: true }`. Una sola vez
por reconexión, no uno por evento perdido: 201 eventos perdidos y un
aviso.

**Y sigue sin recargar por su cuenta.** Un recargón en mitad de una
escritura borra lo que el usuario está escribiendo, que es peor que
mostrar algo un segundo más viejo. Quien quiera recargar se
suscribe al aviso.

fabrica una situación que no ocurre no prueba el caso que importa.

## 2. Los modelos 3D: de dónde salen

Los seis modelos son primitivas generadas. **No hay ningún archivo de
anatomía de otra persona en este repositorio**, y es a propósito.

Para tener anatomía de verdad hay un botón nuevo: **«📂 Abrir .glb»**
en el bloque de la nota. Eliges un archivo del dispositivo, se abre en
el sitio, con etiquetas y oclusión encima. **El archivo no se sube a
ningún servidor**: se queda en tu sesión.

### Las fuentes, con su licencia exacta

| | Licencia | Sirve para |
|---|---|---|
| **BodyParts3D 4.0** | **CC BY 4.0** | 1.838 estructuras, cuerpo masculino adulto. El mejor de la lista. |
| BodyParts3D 3.0 | CC BY-SA 2.1 JP | El clon de GitHub. Share-alike: no lo uses por comodidad. |
| Smithsonian 3D | CC0 | Piezas de museo, instrumental, mummies. No hay un corazón manipulable. |
| Sketchfab | varies | Mirar **modelo a modelo**: hay CC BY y también CC BY-NC. |
| Z-Anatomy, BioDigital | de pago | Licencia propia. No se pueden redistribuir. |

**BodyParts3D cambió de licencia:** la 4.0 es CC BY 4.0 desde el
2025-02-27. Eso importa de verdad — CC BY deja hacer derivados y uso
comercial; CC BY-SA obligaba a compartir igual. La atribripción que
exige es literal:

> BodyParts3D, © The Database Center for Life Science licensed under
> CC Attribution 4.0 International

Todo el detalle, con enlaces, en **`docs/modelos-3d.md`**.

### El crédito, dentro de la aplicación

El bloque 3D tiene un campo `credit` que sale bajo el modelo, y al
cargar tu `.glb` se rellena con el nombre del archivo. No es un adorno:
es el sitio donde la licencia de un modelo ajeno tiene que poder
mostrarse.

### El fallo que se tragaba

`cargarGLB` se tragaba el error y volvía al modelo de ejemplo, y el pie
decía «Corazón — Aurículas, ventrículos…». **Tu archivo no se había
abierto y la pantalla parecía estar bien.** Ahora el motivo sale
escrito: «⚠ No se pudo abrir tu archivo (…)».

Y el `GLTFLoader` local no cargaba porque el archivo de three importa
también `../utils/BufferGeometryUtils.js`, que no existe en `/vendor/`.
Se implementó ahí la única función que usa. El resto de `GLTFLoader`
—el que trae el `import { ... } from 'three'`— se resolvió contra el
namespace global, porque aquí no hay empaquetador.
